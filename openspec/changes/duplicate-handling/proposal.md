## Why

При загрузке документов в индекс нет механизма обнаружения дубликатов. Пользователь может загрузить один и тот же файл несколько раз, не получив предупреждения. При изменении файла и повторной загрузке старая версия остаётся в индексе без пометки. Это приводит к дублированию результатов поиска и усложняет очистку БД.

## What Changes

- При загрузке файла вычислять SHA-256 хеш содержимого и проверять наличие идентичного документа в индексе
- Если дубликат найден и содержимое идентично — пропустить загрузку, вернуть предупреждение
- Если дубликат найден но содержимое отличается — выполнить «мягкое удаление» старой версии: пометить её как устаревшую, не удаляя из БД, чтобы она не попадала в поиск
- Хранить связи между дубликатами для возможности поиска всей цепочки и пакетной очистки
- Добавить новый CLI-инструмент `duplicates list` для просмотра цепочек дубликатов
- Добавить новый CLI-инструмент `duplicates cleanup` для удаления устаревших дубликатов

## Capabilities

### New Capabilities
- `duplicate-tracking` — отслеживание дубликатов документов по хешу содержимого

### Modified Capabilities
- `ingest-file` — расширение семантики ingest_file: возврат статуса при обнаружении дубликата
- `list-files` — добавление полей `isDuplicate` и `duplicateOf` в метаданные файлов

## Impact

- `src/duplicates/` — новый модуль для хранения и управления дубликатами
- `src/server/index.ts` — интеграция в `handleIngestFile` и `handleListFiles`
- `src/cli/duplicates.ts` — новый CLI-подкоманды
- `src/vectordb/types.ts` — расширение метаданных чанков
- `src/vectordb/index.ts` — методы для работы с дубликатами
- `src/vectordb/postgresql.ts` — аналогичные методы для PostgreSQL-бэкенда
- `src/server/tool-definitions.ts` — новые инструменты MCP
- `.env.example` — новая переменная `DUPLICATE_MODE`
