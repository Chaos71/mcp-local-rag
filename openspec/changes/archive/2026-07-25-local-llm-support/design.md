# Дизайн: Поддержка локальных LLM через llama.cpp

## Обзор архитектуры

```
┌─────────────────────────────────────────────────────────┐
│                    RAGServer                            │
│                                                         │
│  ┌──────────────┐    ┌──────────────┐                   │
│  │  Embedder    │    │  Embedder    │                   │
│  │ (Transformers│    │ (llama-cpp)  │                   │
│  │   .js)       │    │              │                   │
│  └──────┬───────┘    └──────┬───────┘                   │
│         │                   │                           │
│         └─────────┬─────────┘                           │
│                   ▼                                     │
│            ┌──────────┐                                 │
│            │  Embed   │  ← единый интерфейс             │
│            └──────────┘                                 │
└─────────────────────────────────────────────────────────┘
```

## Компоненты

### 1. Переменные окружения

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `EMBEDDING_BACKEND` | `transformers` | Бэкенд: `transformers` или `llama-cpp` |
| `LLAMA_CPP_SERVER_URL` | `http://127.0.0.1:8080` | URL сервера llama.cpp |
| `LLAMA_CPP_BATCH_SIZE` | `32` | Размер батча (макс. 128) |
| `LLAMA_CPP_TIMEOUT` | `30000` | Таймаут запроса (мс) |

**Примечание:** Модель и параметры сервера настраиваются при запуске `llama-server` вручную.

### 3. Структура кода

```
src/
├── embedder/
│   ├── index.ts              # Фабрика: выбирает бэкенд по EMBEDDING_BACKEND
│   ├── transformers.ts       # Существующий бэкенд (без изменений)
│   └── llama-cpp.ts          # НОВЫЙ: бэкенд llama.cpp
├── server/
│   ├── types.ts              # Добавить embeddingBackend в RAGServerConfig
│   └── index.ts              # Передать backend в Embedder
├── cli/
│   └── options.ts            # Добавить --embedding-backend флаг
└── server-main.ts            # Добавить парсинг EMBEDDING_BACKEND
```

### 4. Интерфейс Embedder

Единый интерфейс для обоих бэкендов:

```typescript
export interface Embedder {
  embed(text: string): Promise<number[]>
  embedBatch(texts: string[]): Promise<number[][]>
  initialize(): Promise<void>
  dispose(): Promise<void>
  getDimensions(): number  // НОВЫЙ: размерность эмбеддинга
}
```

### 5. Бэкенд llama.cpp

**Реализация:** HTTP-сервер llama.cpp (запускается вручную)

**Запуск сервера (ручной):**
```bash
llama-server --model ./models/Qwen3-Embedding-4B.gguf --port 8080 --embedding
```

**API для эмбеддингов:**
```
POST http://127.0.0.1:8080/embed
{
  "input": "text to embed"
}
```

**Ответ:**
```json
{
  "embedding": [0.1, 0.2, 0.3, ...],
  "model": "Qwen/Qwen3-Embedding-4B"
}
```

**Размерность эмбеддингов Qwen3-Embedding-4B:** 4096

**Преимущества:**
- Не требует native Node.js binding
- Можно запускать как отдельный процесс
- Поддержка GPU (через CUDA/Vulkan)
- Простая интеграция через HTTP

**Недостатки:**
- Требуется отдельный процесс сервера
- Небольшая задержка на HTTP-запрос

### 6. Безопасность

- Путь к модели проверяется на отсутствие sensitive directories
- Сервер llama.cpp по умолчанию привязан к `127.0.0.1` (только локальный доступ)
- Размер батча ограничен `LLAMA_CPP_BATCH_SIZE` (макс. 128)

### 7. Обратная совместимость

- `EMBEDDING_BACKEND` по умолчанию = `transformers`
- Существующие конфигурации не меняются
- Transformers.js бэкенд работает без изменений

### 8. Обработка ошибок

- Если сервер llama.cpp недоступен — ошибка при попытке эмбеддинга
- Если модель не найдена — ошибка при инициализации
- Таймауты: 30 секунд на запрос, 60 секунд на инициализацию

## Альтернативы рассмотрены

### Вариант A: Встроенный инференс через Node.js binding

**Плюсы:**
- Нет необходимости в отдельном процессе
- Меньше задержка
- Проще управление жизненным циклом

**Минусы:**
- Требует native compilation (node-addon-api)
- Больше сложность поддержки
- Зависимость от платформы

**Решение:** Выбран вариант B (HTTP-сервер) для минимизации зависимостей.

### Вариант B: HTTP-сервер llama.cpp (выбрано)

**Плюсы:**
- Нет native binding
- Гибкость: сервер может быть на другом устройстве
- Поддержка GPU из коробки
- Простая интеграция

**Минусы:**
- Требуется отдельный процесс
- HTTP-задержка (~5-15ms на запрос)
