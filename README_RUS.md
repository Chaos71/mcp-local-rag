Локальный RAG для разработчиков через MCP или CLI.
Семантический поиск с повышением по ключевым словам для точных технических терминов — полностью приватный, без настройки.

## Возможности

- **Семантический поиск с повышением по ключевым словам**
  Сначала векторный поиск, затем ключевые совпадения повышают точные совпадения. Такие термины, как `useEffect`, коды ошибок и имена классов ранжируются выше — не только по семантическому предположению.

- **Умное семантическое чанкирование**
  Разбивает документы по смыслу, а не по количеству символов. Использует семантическое сходство для поиска естественных границ тем — сохраняет связанный контент вместе и разбивает там, где меняются темы.

- **Фильтрация результатов с приоритетом качества**
  Группирует результаты по разрывам релевантности вместо произвольного ограничения top-K. Получайте меньше, но более надёжных чанков.

- **Работает полностью локально**
  Никаких API-ключей, облака, данных, покидающих ваш компьютер. Работает полностью офлайн после первой загрузки модели.

- **Настройка без трения**
  Одна команда `npx`. Без Docker, Python, управления серверами.
  Используйте через MCP, CLI или оба. Опциональные [Agent Skills](#agent-skills) помогают ИИ-ассистентам формировать лучшие запросы и интерпретировать результаты.

## Быстрый старт

Установите `BASE_DIR` в папку, которую хотите искать (или `BASE_DIRS` для нескольких корневых директорий — см. [Конфигурация](#конфигурация)). Документы должны находиться в одной из настроенных корневых директорий.

Добавьте MCP-сервер в ваш ИИ-инструмент для кодирования:

**Для Cursor** — добавьте в `~/.cursor/mcp.json`:
```json
{
  "mcpServers": {
    "local-rag": {
      "command": "npx",
      "args": ["-y", "mcp-local-rag"],
      "env": {
        "BASE_DIR": "/путь/к/вашим/документам"
      }
    }
  }
}
```

**Для Codex** — добавьте в `~/.codex/config.toml`:
```toml
[mcp_servers.local-rag]
command = "npx"
args = ["-y", "mcp-local-rag"]

[mcp_servers.local-rag.env]
BASE_DIR = "/путь/к/вашим/документам"
```

**Для Claude Code** — выполните эту команду:
```bash
claude mcp add local-rag --scope user --env BASE_DIR=/путь/к/вашим/документам -- npx -y mcp-local-rag
```

Перезапустите ваш инструмент, затем начните использовать:

```
Вы: "Загрузить api-spec.pdf"
Ассистент: Успешно загружен api-spec.pdf (создано 47 чанков)

Вы: "Что говорит API-документация об аутентификации?"
Ассистент: Согласно документации, аутентификация использует OAuth 2.0 с JWT-токенами.
          Процесс описан в разделе 3.2...
```

**Или используйте напрямую как CLI** — MCP-сервер не нужен:

```bash
npx mcp-local-rag ingest ./docs/
npx mcp-local-rag query "API аутентификации"
```

Всё. Без Docker, без Python, без настройки сервера.

## Зачем это нужно

Вы хотите, чтобы ИИ искал ваши документы — технические спецификации, исследовательские статьи, внутренние документы. Но большинство решений отправляют ваши файлы во внешние API.

**Приватность.** Ваши документы могут содержать конфиденциальные данные. Это работает полностью локально.

**Стоимость.** Внешние API эмбеддингов взимают плату за использование. Это бесплатно после первоначальной загрузки модели.

**Офлайн.** Работает без интернета после настройки.

**Поиск по коду.** Чистый семантический поиск пропускает точные термины вроде `useEffect` или `ERR_CONNECTION_REFUSED`. Повышение по ключевым словам ловит и смысл, и точные совпадения.

**Реальность агентов.** На практике во многих ИИ-средах основное использование — вызов инструментов. Поддержка CLI и Agent Skills делает те же рабочие процессы доступными даже без полной интеграции MCP.

## Использование

mcp-local-rag предоставляет два интерфейса: **MCP-сервер** для ИИ-инструментов для кодирования и **CLI** для прямого использования из терминала.

### Использование с MCP

MCP-сервер предоставляет 7 инструментов: `ingest_file`, `ingest_data`, `query_documents`, `read_chunk_neighbors`, `list_files`, `delete_file`, `status`.

#### Загрузка документов

```
"Загрузить документ по адресу /Users/me/docs/api-spec.pdf"
```

Поддерживает PDF, DOCX, TXT и Markdown. Сервер извлекает текст, разбивает его на чанки, генерирует эмбеддинги локально и сохраняет всё в локальную векторную базу данных.

Повторная загрузка того же файла автоматически заменяет старую версию.

##### Загрузка PDF с рисунками (визуальный режим)

PDF-файлы с графиками, таблицами или диаграммами могут опционально добавлять локальные подписи, сгенерированные VLM, в индекс документа, предоставляя визуальному контенту некоторый поиск в том же векторном + FTS-конвейере. Подписи — это вспомогательный текст — не поиск изображений, не OCR и не точная транскрипция рисунка.

**Через MCP**:
```
"Загрузить /Users/me/docs/api-spec.pdf с visual: true"
```

**Через CLI**:
```bash
npx mcp-local-rag ingest ./docs/spec.pdf --visual
```

Каждая подпись генерируется как отдельный чанк с обёрткой `[Визуальный контент на странице N: …]`, вместе с чанками тела страницы. Она проходит через существующий эмбеддер и FTS-индекс — без различий в схеме, без отдельного индекса.

Визуальный режим включается опционально; обычная загрузка не загружает VLM. Сбои VLM на каждой странице допускаются — эта страница обрабатывается только с текстом.

###### Выбор профиля визуального качества

Визуальный режим предлагает два профиля, выбираемых для каждого вызова загрузки:

| Профиль | Модель | Диск (кэш) | Вывод на страницу | Предназначен для |
|---|---|---|---|---|
| `fast` (по умолчанию) | `HuggingFaceTB/SmolVLM-256M-Instruct` | ~250 МБ | базовый | Лёгкая визуальная индексация, быстрая настройка первого запуска. |
| `quality` | `onnx-community/Qwen2.5-VL-3B-Instruct-ONNX` | ~2.9 ГБ | ~2× `fast` | Рисунки с текстом внутри изображения (подписи осей, подписи панелей, аннотации), где точность подписи важнее времени вывода. |

Числа выше измерены на CPU во время разработки на тестовых PDF проекта; они могут меняться при обновлениях модели или отличаться на вашем оборудовании.

**Через MCP** — `ingest_file` принимает опциональный параметр `visualQuality` (enum: `'fast' | 'quality'`, по умолчанию `'fast'`; игнорируется, когда `visual` равно false):
```
"Загрузить /Users/me/docs/research-paper.pdf с visual: true и visualQuality: 'quality'"
```

**Через CLI** — `--visual-quality fast|quality` (по умолчанию `fast`; молча игнорируется, когда `--visual` отсутствует):
```bash
npx mcp-local-rag ingest ./docs/research-paper.pdf --visual --visual-quality quality
```

Идентификаторы моделей профиля и варианты квантизации фиксированы для каждого релиза. Оба профиля разделяют один `CACHE_DIR` (по умолчанию: `./models/`); первый запуск каждого профиля загружает его модель.

> **Изменение поведения с v0.14.0:** Подписи теперь генерируются как отдельные чанки, а не добавляются к тексту страницы перед чанкированием. Как побочный эффект, `metadata.fileSize` для визуальных загрузок больше не включает количество символов подписи — он измеряет длину тела после извлечения. Сам PDF не меняется; только сообщаемый `fileSize` для визуально загруженных PDF может уменьшиться при переходе через границу релиза.

> **Примечание по безопасности:** Визуальные подписи выводятся из содержимого PDF и могут наследовать текст, контролируемый злоумышленником. Потребители LLM на downstream должны рассматривать извлечённые чанки как ненадёжные данные, а не как инструкции. Обёртка `[Визуальный контент на странице N: …]` помогает потребителям отличать текст подписи от прозы.

#### Загрузка HTML-контента

Используйте `ingest_data` для загрузки HTML-контента, полученного вашим ИИ-ассистентом (через веб-загрузку, curl, инструменты браузера и т.д.):

```
"Загрузить https://example.com/docs и загрузить HTML"
```

Сервер извлекает основное содержимое с помощью Readability (удаляет навигацию, рекламу и т.д.), преобразует в Markdown и индексирует. Идеально подходит для:
- Веб-документации
- HTML, полученного ИИ-ассистентом
- Содержимого из буфера обмена

HTML автоматически очищается — вы получаете содержимое статьи, а не шаблонный код.

> **Примечание:** Сам RAG-сервер не загружает веб-контент — ваш ИИ-ассистент получает его и передаёт HTML в `ingest_data`. Это сохраняет сервер полностью локальным, позволяя вам индексировать любой контент, к которому может получить доступ ваш ассистент. Пожалуйста, уважайте условия обслуживания сайтов и авторские права при загрузке внешнего контента.

#### Поиск документов

```
"Что говорит API-документация об аутентификации?"
"Найдите информацию об ограничении скорости"
"Поиск лучших практик обработки ошибок"
```

Поиск использует семантическое сходство с повышением по ключевым словам. Это означает, что `useEffect` находит документы, содержащие этот точный термин, а не только семантически похожие концепции React.

Результаты включают текстовое содержимое, исходный файл, название документа и оценку релевантности. Название документа предоставляет контекст для каждого чанка, помогая идентифицировать, какому документу принадлежит результат. Настройте количество результатов с помощью `limit` (1-20, по умолчанию 10).

Сужайте поиск до части корпуса с помощью `scope` — один префикс пути или их список. Результаты ограничиваются чанками, чей путь к файлу равен префиксу или находится под ним (точное или потомок). Например, `"/docs/api"` совпадает с `/docs/api` и `/docs/api/auth.md`, но не с `/docs/apiv2`; префикс файла вроде `"/docs/readme.md"` совпадает только с этим файлом. Передавайте префиксы в стиле пути ОС сервера.

#### Расширение контекста вокруг результата

Когда результат поиска требует больше окружающего контекста, используйте `read_chunk_neighbors` для чтения чанков до и после него:

```
"Этот результат об аутентификации выглядит релевантным — прочитайте окружающие чанки для полного объяснения"
```

Передайте `filePath` и `chunkIndex` из результата поиска. Ответ включает целевой чанк (отмечен `isTarget: true`) плюс его соседей, отсортированных по индексу чанка. По умолчанию 2 чанка до и 2 после (можно настроить до 50 каждого).

#### Управление файлами

```
"Перечислить все файлы в настроенных корневых директориях и их статус загрузки"   # Посмотреть, что проиндексировано
"Удалить old-spec.pdf из RAG"     # Удалить файл
"Показать статус RAG-сервера"     # Проверить здоровье системы
```

Сужайте список с помощью `scope` на `list_files` — один префикс пути или их список. Результаты ограничиваются файлами, доступными по пути, равному или находящемуся под префиксом (точное или потомок); например, `"/docs/api"` совпадает с `/docs/api` и `/docs/api/auth.md`, но не с `/docs/apiv2`. Источники сырых данных (от `ingest_data`) остаются в списке независимо от scope. На больших объёмах scope также ускоряет список, пропуская директории вне scope во время сканирования.

### Использование как CLI

Все инструменты MCP также доступны как команды CLI — MCP-сервер не нужен:

```bash
npx mcp-local-rag ingest ./docs/               # Массовая загрузка файлов
npx mcp-local-rag query "API аутентификации"    # Поиск документов
npx mcp-local-rag query "auth" --scope /docs/api --scope /docs/guide  # Ограничить префиксами путей (повторяется)
npx mcp-local-rag read-neighbors --file-path /abs/path.md --chunk-index 5  # Расширить контекст
npx mcp-local-rag list                          # Показать статус загрузки
npx mcp-local-rag list --scope /docs/api --scope /docs/guide  # Ограничить список префиксами путей (повторяется)
npx mcp-local-rag status                        # Статистика базы данных
npx mcp-local-rag delete ./docs/old.pdf         # Удалить содержимое
npx mcp-local-rag delete --source "https://..."  # Удалить по URL источника
npx mcp-local-rag duplicates list               # Показать группы дубликатов
npx mcp-local-rag duplicates list --include-deprecated --format json  # Включить deprecated в формате JSON
npx mcp-local-rag duplicates cleanup --dry-run  # Предпросмотр очистки без выполнения
```

`query`, `read-neighbors`, `list`, `status` и `delete` выводят JSON в stdout для конвейеризации (например, `| jq`). `ingest` выводит прогресс в stderr. Глобальные опции (`--db-path`, `--cache-dir`, `--model-name`) идут перед подкомандой. Запустите `npx mcp-local-rag --help` для подробностей.

> ⚠️ CLI **не читает** вашу конфигурацию MCP-клиента (`mcp.json`, `config.toml` и т.д.). Настройте CLI через флаги или переменные окружения, как показано ниже.

### Примеры командной строки

#### Базовое использование

```bash
# Загрузка одного файла
npx mcp-local-rag ingest ./docs/api-spec.pdf

# Загрузка всей директории
npx mcp-local-rag ingest ./docs/

# Поиск по документам
npx mcp-local-rag query "API аутентификации"

# Поиск с пользовательским лимитом
npx mcp-local-rag query "аутентификация" --limit 5

# Показать все загруженные файлы
npx mcp-local-rag list

# Показать статистику базы данных
npx mcp-local-rag status
```

#### Использование пользовательских путей

```bash
# Использовать пользовательское расположение базы данных
npx mcp-local-rag --db-path ./my-db query "аутентификация"

# Использовать пользовательскую директорию кэша моделей
npx mcp-local-rag --cache-dir ./cache query "поисковый запрос"

# Использовать пользовательскую модель (должна совпадать с MODEL_NAME MCP-сервера)
npx mcp-local-rag --model-name Xenova/all-MiniLM-L6-v2 query "поиск"
```

#### Директории с несколькими корнями

```bash
# Загрузка с несколькими корнями документов
npx mcp-local-rag ingest --base-dir ./docs --base-dir ./specs ./docs/readme.md

# Показать файлы из конкретных корней
npx mcp-local-rag list --base-dir ./docs --base-dir ./specs

# Поиск только в документации API
npx mcp-local-rag query "auth" --scope /docs/api
```

#### Настройка поиска

```bash
# Поиск с повышением по ключевым словам (выше значение = сильнее повышение)
RAG_HYBRID_WEIGHT=0.7 npx mcp-local-rag query "useEffect"

# Получить только верхнюю группу результатов
RAG_GROUPING=similar npx mcp-local-rag query "обработка ошибок"

# Фильтрация по порогу релевантности
RAG_MAX_DISTANCE=0.5 npx mcp-local-rag query "аутентификация"

# Ограничить одним лучшим файлом
RAG_MAX_FILES=1 npx mcp-local-rag query "документация API"
```

#### Использование бэкенда llama.cpp

```bash
# Загрузка с бэкендом llama.cpp
EMBEDDING_BACKEND=llama-cpp LLAMA_CPP_SERVER_URL=http://127.0.0.1:8080 \
  npx mcp-local-rag ingest ./docs/

# Поиск с бэкендом llama.cpp
EMBEDDING_BACKEND=llama-cpp LLAMA_CPP_BATCH_SIZE=32 \
  npx mcp-local-rag query "технические термины"
```

#### Визуальный режим PDF

```bash
# Загрузка PDF с визуальными подписями (профиль fast)
npx mcp-local-rag ingest ./docs/paper.pdf --visual

# Загрузка PDF с профилем качества
npx mcp-local-rag ingest ./docs/paper.pdf --visual --visual-quality quality
```

#### Конвейеризация результатов

```bash
# Поиск и фильтрация с помощью jq
npx mcp-local-rag query "аутентификация" | jq '.results[] | select(.score > 0.7)'

# Поиск и подсчёт результатов
npx mcp-local-rag query "обработка ошибок" | jq '.results | length'

# Поиск и извлечение только путей к файлам
npx mcp-local-rag query "API" | jq -r '.results[].filePath'
```

#### Конфигурация с переменными окружения

```bash
# Установить всю конфигурацию в одной команде
export BASE_DIR=./docs
export DB_PATH=./lancedb
export RAG_HYBRID_WEIGHT=0.7

npx mcp-local-rag query "аутентификация"
```

#### Приоритет конфигурации

1. **Флаги CLI** (наивысший приоритет) — `npx mcp-local-rag --db-path ./my-db query "auth"`
2. **Переменные окружения** — `export DB_PATH=./my-db && npx mcp-local-rag query "auth"`
3. **Значения по умолчанию** — применяются, когда не установлены ни флаги, ни env-переменные

> ⚠️ CLI **не читает** вашу конфигурацию MCP-клиента (`mcp.json`, `config.toml` и т.д.). Настройте CLI через флаги или переменные окружения, как показано ниже.

#### Конфигурация

**Флаги CLI** — глобальные опции идут перед подкомандой, опции подкоманды — после:

```bash
npx mcp-local-rag --db-path ./my-db query "auth" --base-dir ./docs
```

Флаг `--base-dir` повторяется на `ingest` и `list`; передавайте его один раз для каждого корня:

```bash
npx mcp-local-rag ingest --base-dir ./docs --base-dir ./specs ./docs/readme.md
npx mcp-local-rag list --base-dir ./docs --base-dir ./specs
```

Позиционный путь к `ingest` должен находиться в одной из настроенных корневых директорий. Когда хотя бы один `--base-dir` предоставлен, корни CLI заменяют любые корни из env-переменных (без объединения).

**Переменные окружения** — установите в вашей оболочке:

```bash
export DB_PATH=./my-db
export BASE_DIR=./docs
npx mcp-local-rag query "auth"
```

Для нескольких корней используйте `BASE_DIRS` (JSON-массив непустых строк путей):

```bash
export BASE_DIRS='["/Users/me/Documents/work","/Users/me/Projects/specs"]'
npx mcp-local-rag list
```

**Общий конфиг между MCP и CLI** — если ваш MCP-клиент наследует переменные окружения оболочки, вы можете установить их в вашем профиле оболочки (например, `~/.zshrc`), чтобы оба использовали одни и те же значения. В противном случае установите их явно в вашей MCP-конфигурации также.

```bash
export BASE_DIR=/путь/к/вашим/документам
export DB_PATH=/путь/к/lancedb
```

Конфигурация разрешается в этом порядке:

1. Флаги CLI (наивысший приоритет)
2. Переменные окружения
3. Значения по умолчанию

Полный список флагов CLI, переменных окружения и значений по умолчанию см. в [Конфигурация](#конфигурация).

Для установок только CLI (без MCP-сервера) установите [Agent Skills](#agent-skills), чтобы ваш ИИ-ассистент мог формировать лучшие запросы и последовательно интерпретировать результаты.

> ⚠️ **Флаг CLI `--model-name` должен совпадать с env-переменной MCP-сервера `MODEL_NAME`.** Использование другой модели эмбеддингов против существующей базы данных производит несовместимые векторы, молча ухудшая качество поиска.

## Настройка поиска

Настройте эти для вашего случая использования:

| Переменная | По умолчанию | Описание |
|----------|---------|-------------|
| `RAG_HYBRID_WEIGHT` | `0.6` | Фактор повышения по ключевым словам. 0 = только семантика, выше = сильнее повышение по ключевым словам. |
| `RAG_GROUPING` | (не установлено) | `similar` для только верхней группы, `related` для топ 2 групп. |
| `RAG_MAX_DISTANCE` | (не установлено) | Фильтровать результаты с низкой релевантностью (например, `0.5`). |
| `RAG_MAX_FILES` | (не установлено) | Ограничить результаты топ N файлами (например, `1` для лучшего одного файла). |

### Настройка для кода

Для кодовых баз и API-спецификаций увеличьте повышение по ключевым словам, чтобы точные идентификаторы (`useEffect`, `ERR_*`, имена классов) доминировали в ранжировании:

```json
"env": {
  "RAG_HYBRID_WEIGHT": "0.7",
  "RAG_GROUPING": "similar"
}
```

- `0.7` — сбалансированная семантика + ключевые слова
- `1.0` — агрессивный; точные совпадения сильно переранжируют результаты

Повышение по ключевым словам применяется *после* семантической фильтрации, поэтому оно улучшает точность без выявления нерелевантных совпадений.

## Как это работает

**TL;DR:**
- Документы разбиваются на чанки по семантическому сходству, а не по фиксированному количеству символов
- Каждый чанк эмбеддится локально с помощью Transformers.js
- Поиск использует семантическое сходство с повышением по ключевым словам для точных совпадений
- Результаты фильтруются на основе разрывов релевантности, а не сырых оценок

### Подробности

При загрузке документа парсер извлекает текст в зависимости от типа файла (PDF через `mupdf`, DOCX через `mammoth`, текстовые файлы напрямую).

Семантический чанкер разбивает текст на предложения, затем группирует их с использованием семантического сходства. Он находит естественные границы тем, где смысл меняется — сохраняя связанный контент вместе вместо произвольного ограничения по символам. Это производит чанки, которые являются согласованными единицами смысла, обычно 500-1000 символов. Markdown-блоки кода сохраняются целыми — никогда не разбиваются посередине блока — сохраняя код, готовый к копированию, в результатах поиска.

### Семантическое чанкирование: алгоритм Max-Min

**Принцип работы:**

```
Документ: "Привет мир. Как дела? Всё хорошо. Спасибо. До свидания."
                    ↓
Семантический анализ сходства:
  [1]↔[2]: 0.95  (одна тема)
  [2]↔[3]: 0.45  (разные темы!)
  [3]↔[4]: 0.80  (близкие темы)
  [4]↔[5]: 0.30  (разные темы!)
                    ↓
Результат: 3 чанка
  Чанк 1: "Привет мир. Как дела?"
  Чанк 2: "Всё хорошо. Спасибо."
  Чанк 3: "До свидания."
```

**Пошаговый алгоритм:**

1. **Разбиение на предложения** — текст разделяется на отдельные предложения
2. **Генерация эмбеддингов** — каждое предложение преобразуется в вектор
3. **Принятие решения** — для каждого предложения проверяется:

```
Для предложения i проверяем:
┌─────────────────────────────────────────────────────┐
│  maxSim = max(cosine(s[i], s[1..i-1]))              │
│  minSim = min(cosine(s[1..i-1], s[1..i-1]))         │
│                                                     │
│  threshold = max(c * minSim * sigmoid(chunkSize),   │
│                  hardThreshold)                      │
│                                                     │
│  if maxSim > threshold → добавляем в чанк          │
│  else → начинаем новый чанк                         │
└─────────────────────────────────────────────────────┘
```

**Пример с числами:**

Предположим, `hardThreshold = 0.3`, `c = 0.9`, `initConst = 1.5`:

| Шаг | Предложение | similarity | Проверка | Решение |
|-----|-------------|------------|----------|---------|
| 1 | "Аутентификация через JWT..." | — | — | Начинаем чанк |
| 2 | "Токен содержит заголовок..." | 0.92 | `1.5 × 0.92 = 1.38 > 0.3` ✅ | Добавляем |
| 3 | "Обновление токена..." | 0.85 | `threshold = max(0.9 × 0.92 × 0.88, 0.3) = 0.73`<br>`0.85 > 0.73` ✅ | Добавляем |
| 4 | "Ошибка 401 возвращается..." | 0.25 | `threshold = max(0.9 × 0.88 × 0.95, 0.3) = 0.75`<br>`0.25 > 0.75` ❌ | Новый чанк |

**Итог:**

```
Чанк 1 (3 предложения):
"Аутентификация через JWT используется в современных API.
Токен содержит заголовок, полезную нагрузку и подпись.
Обновление токена происходит автоматически."

Чанк 2 (1 предложение):
"Ошибка 401 возвращается при истечении срока действия."
```

**Оптимизация производительности:**

```typescript
// Без окна: O(n²) — сравниваем каждое предложение со ВСЕМИ в чанке
for (i in chunk) {
  for (j in chunk) {
    cosine(chunk[i], chunk[j])  // 100 предложений = 10,000 сравнений
  }
}

// С окном: O(1) — сравниваем только последние 5
const startIdx = max(0, embeddings.length - WINDOW_SIZE)
const window = embeddings.slice(startIdx)  // максимум 5
// 5 предложений = 10 сравнений
```

**Влияние параметров на результат:**

| Параметр | Низкое значение | Высокое значение |
|----------|-----------------|------------------|
| `hardThreshold` | Меньше чанков, больше текста | Больше чанков, меньше текста |
| `c` | Чанки растут быстрее | Чанки делятся чаще |
| `minChunkLength` | Меньше мусорных чанков | Больше слияний коротких |

**Пример: как меняется разбиение**

Текст: Техническая документация API (5000 слов)

| Модель | hardThreshold | Кол-во чанков | Средний размер |
|--------|---------------|---------------|----------------|
| all-MiniLM-L6-v2 | 0.6 | ~400 | 12 слов |
| Qwen3-VL-2B | 0.6 | ~1200 | 4 слова |
| Qwen3-VL-2B | 0.3 | ~600 | 8 слов |
| Qwen3-VL-2B | 0.15 | ~250 | 20 слов |

> **Важно для современных моделей:** Параметры чанкера калиброваны для `all-MiniLM-L6-v2` (384-dim). Для Qwen3-Embedding-4B, nomic-embed-text-v1.5 и других современных моделей снизьте `CHUNKER_HARD_THRESHOLD` до 0.1–0.4, чтобы избежать избыточного разбиения.

Настройка через переменные окружения:

```bash
# Для Qwen3-Embedding-4B или Qwen3-VL-Embedding-2B
export CHUNKER_HARD_THRESHOLD=0.15
export CHUNKER_MIN_LENGTH=100
```

Полный список параметров:

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `CHUNKER_HARD_THRESHOLD` | `0.6` | Жёсткий порог минимального сходства (0.0–1.0) |
| `CHUNKER_INIT_CONST` | `1.5` | Начальный константный множитель для первой пары предложений |
| `CHUNKER_C` | `0.9` | Масштабирующий множитель для расчёта порога |
| `CHUNKER_MIN_LENGTH` | `50` | Минимальная длина чанка в символах |

Каждый чанк проходит через модель эмбеддингов Transformers.js (по умолчанию: `all-MiniLM-L6-v2`, настраивается через `MODEL_NAME`), преобразуя текст в векторы. Векторы хранятся в LanceDB, файловой векторной базе данных, не требующей процесса сервера.

При поиске:
1. Ваш запрос становится вектором с помощью той же модели
2. Семантический (векторный) поиск находит наиболее релевантные чанки
3. Применяются фильтры качества (порог расстояния, группировка)
4. Ключевые совпадения повышают ранжирование для точного совпадения терминов

Повышение по ключевым словам обеспечивает, чтобы точные термины вроде `useEffect` или коды ошибок ранжировались выше при совпадении.

- Кодовые репозитории → по умолчанию часто достаточно; повышение по ключевым словам важнее (или `jinaai/jina-embeddings-v2-base-code`)

### Бэкенд llama.cpp (локальная LLM)

Для пользователей, которые хотят использовать современные модели эмбеддингов, доступные только в формате GGUF (например, **Qwen3-Embedding-4B**, **nomic-embed-text-v1.5**), mcp-local-rag поддерживает вторичный бэкенд эмбеддингов, работающий через llama.cpp.

**Поддерживаемые модели:**

| Модель | Размерность | Источник |
|--------|-------------|----------|
| Qwen/Qwen3-Embedding-4B | 4096 | [HuggingFace](https://huggingface.co/Qwen/Qwen3-Embedding-4B) |
| nomic-ai/nomic-embed-text-v1.5 | 768 | [HuggingFace](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5) |

**Настройка:**

1. Установите llama.cpp и скачайте GGUF-модель эмбеддингов:
   ```bash
   # Скачайте Qwen3-Embedding-4B
   huggingface-cli download Qwen/Qwen3-Embedding-4B --include "*.gguf"
   ```

2. Запустите сервер llama.cpp:
   ```bash
   llama-server --model ./Qwen3-Embedding-4B.gguf --port 8080 --embedding
   ```

3. Настройте mcp-local-rag на использование бэкенда llama.cpp:

   **MCP-клиент (Cursor/Codex/Claude Code):**
   ```json
   {
     "mcpServers": {
       "local-rag": {
         "command": "npx",
         "args": ["-y", "mcp-local-rag"],
         "env": {
           "BASE_DIR": "/путь/к/вашим/документам",
           "EMBEDDING_BACKEND": "llama-cpp",
           "LLAMA_CPP_SERVER_URL": "http://127.0.0.1:8080"
         }
       }
     }
   }
   ```

   **CLI:**
   ```bash
   EMBEDDING_BACKEND=llama-cpp LLAMA_CPP_SERVER_URL=http://127.0.0.1:8080 \
     npx mcp-local-rag ingest ./docs/
   ```

**Параметры конфигурации:**

| Переменная окружения | Флаг CLI | По умолчанию | Описание |
|---------------------|----------|---------|----------|
| `EMBEDDING_BACKEND` | `--embedding-backend` | `transformers` | Бэкенд: `transformers` или `llama-cpp` |
| `LLAMA_CPP_SERVER_URL` | — | `http://127.0.0.1:8080` | URL сервера llama.cpp |
| `LLAMA_CPP_BATCH_SIZE` | — | `16` | Размер батча (1–128). Тексты отправляются пакетно одним HTTP-запросом `input: string[]`. |
| `LLAMA_CPP_BATCH_INTERVAL` | — | `1000` | Интервал между батчами запросов к серверу llama.cpp (мс). Помогает избежать rate limiting при высокой нагрузке. |
| `LLAMA_CPP_TIMEOUT` | — | `30000` | Таймаут запроса в миллисекундах (1000–300000) |
| `RAG_LLAMA_CPP_DIMENSIONS` | — | `4096` | Переопределение размерности эмбеддингов (для моделей не-Qwen3) |

**Преимущества:**
- Доступ к современным GGUF-моделям, недоступным в Transformers.js
- Ускорение через GPU via CUDA/Vulkan (если поддерживается вашим оборудованием)
- Сервер может работать на отдельной машине

**Ограничения:**
- Требуется отдельный процесс сервера llama.cpp
- HTTP-задержка (~5-15 мс на запрос)
- Нет автоматического управления моделями

### PostgreSQL как бэкенд векторной БД

### Обработка дубликатов

mcp-local-rag отслеживает дубликаты документов с помощью хеширования содержимого SHA-256. При повторной загрузке одного и того же файла (по содержимому) система может пропустить его, обновить существующую запись или сохранить обе версии.

**Режимы:**

| Режим | Поведение |
|-------|----------|
| `skip` (по умолчанию) | Пропустить загрузку, вернуть предупреждение |
| `update` | Обновить существующий документ (пометить старые чанки как deprecated) |
| `track` | Сохранить оба экземпляра с пометкой о дубликате |

**Настройка:**

Через переменную окружения:
```bash
export DUPLICATE_MODE=skip
```

Через CLI-флаг (подкоманда `ingest`):
```bash
npx mcp-local-rag --duplicate-mode update ingest ./docs/
```

**Вывод CLI:**

При загрузке дубликата CLI выводит статус:
```
[1/3] ./docs/guide.pdf ... OK (42 chunks)
[2/3] ./docs/guide.pdf ... OK (42 chunks) (updated, dup: ./docs/guide.pdf)
[3/3] ./docs/other.pdf ... OK (15 chunks)
```

**Механизм:**

1. Перед чанкированием вычисляется SHA-256 хеш содержимого
2. `vectorStore.getDuplicatesByHash()` проверяет наличие дубликатов в БД
3. При обнаружении дубликата применяется выбранный режим:
   - `skip`: загрузка отменяется, чанки не вставляются
   - `update`: старые чанки помечаются как deprecated через `vectorStore.markDeprecated()`
   - `track`: оба экземпляра сохраняются без изменений

**Изменения схемы:**

- **LanceDB:** Добавлен столбец `status` (active/deprecated) и столбец `contentHash` в таблицу chunks; создаёт таблицу `duplicates` при первой вставке.
- **PostgreSQL:** Добавлен столбец `status` в таблицу `chunks`; создаёт таблицу `duplicates` при `initialize()`.

**CLI-подкоманды:**

Две новые CLI-подкоманды управляют дубликатами документов:

```bash
# Показать все группы дубликатов
npx mcp-local-rag duplicates list

# Показать с включёнными deprecated-записями
npx mcp-local-rag duplicates list --include-deprecated

# Вывести в формате JSON для конвейеризации
npx mcp-local-rag duplicates list --format json

# Предпросмотр очистки без выполнения
npx mcp-local-rag duplicates cleanup --dry-run

# Выполнить очистку (удаляет deprecated-чанки)
npx mcp-local-rag duplicates cleanup
```

**Опции `duplicates list`:**

| Опция | Описание |
|-------|----------|
| `--include-deprecated` | Включить deprecated-записи в результаты |
| `--format <format>` | Формат вывода: `human` или `json` (по умолчанию: `human`) |
| `-h, --help` | Показать справку |

**Опции `duplicates cleanup`:**

| Опция | Описание |
|-------|----------|
| `--dry-run` | Показать, что будет удалено, без фактического удаления |
| `-h, --help` | Показать справку |

**Пример вывода (human-readable):**

```
Найдено 2 группы дубликатов, всего 5 дубликатов

Хеш: a1b2c3d4e5f6...
  Файлы:
    - /Users/me/docs/api-spec.pdf
    - /Users/me/docs/api-spec-backup.pdf

Хеш: f6e5d4c3b2a1...
  Файлы:
    - /Users/me/docs/guide.pdf
    - /Users/me/docs/guide.pdf [deprecated]
    - /Users/me/docs/guide-old.pdf
```

**Реализовано:**

- Вычисление хеша содержимого SHA-256 в `handleIngestFile` (MCP-сервер) и `ingestSingleFile` (CLI) через `computeContentHash()`
- Поле `IngestResult.contentHash`: SHA-256 hex digest (64 символа) или `null` при ошибке вычисления
- Поле `IngestResult.status`: `'new' | 'skipped' | 'updated' | 'tracked'`
- Логика обнаружения дубликатов в конвейере загрузки с поддержкой `DUPLICATE_MODE` (MCP и CLI)
- CLI-флаг `--duplicate-mode` для подкоманды ingest
- Класс `DuplicateStore` с методами `add()`, `findByHash()`, `findDuplicates()`, `getAll()`, `remove()`
- Поле `isDuplicate` в `IngestedFileSummary` для `list_files` — возвращается в ответе инструмента `list_files` и CLI-подкоманде `list`

**В следующей итерации:**

- Инструменты MCP: `list_duplicates`, `cleanup_duplicates`
- Валидация `DUPLICATE_MODE` в `tool-input.ts`
- Unit-тесты для `computeContentHash()` и `DuplicateStore`
- Integration-тесты для `handleIngestFile` с дубликатами

### Корневые директории документов (`BASE_DIR` и `BASE_DIRS`)

mcp-local-rag обеспечивает границу безопасности: только файлы в пределах настроенного корня доступны для операций загрузки, списка, удаления или чтения соседей.

**Один корень** — используйте `BASE_DIR`:

```bash
export BASE_DIR=/Users/me/Documents/work
```

**Несколько корней** — используйте `BASE_DIRS` с JSON-массивом:

```bash
export BASE_DIRS='["/Users/me/Documents/work","/Users/me/Projects/specs"]'
```

Поддерживается только синтаксис JSON-массива. Синтаксис разделителя вроде `BASE_DIRS=/a:/b` намеренно **не** поддерживается (избегает неоднозначности с пробелами, двоеточиями, запятыми и путями Windows).

**Порядок разрешения** (от высшего приоритета):

1. Флаги CLI `--base-dir <path>` (повторяется на `ingest` и `list`)
2. Переменная окружения `BASE_DIRS`
3. Переменная окружения `BASE_DIR`
4. `process.cwd()` (текущая рабочая директория)

Корни CLI **заменяют** корни env — они никогда не объединяются. `BASE_DIRS` и `BASE_DIR` также никогда не объединяются: `BASE_DIRS` побеждает, когда оба установлены.

**Предупреждение о приоритете** — когда `BASE_DIRS` и `BASE_DIR` оба установлены (и CLI `--base-dir` не предоставлен), `BASE_DIR` игнорируется и отображается предупреждение. Предупреждение видно:

- В ответах инструментов MCP (как дополнительный блок содержимого, на каждом инструменте — включая `status`, `query_documents`, `ingest_file`, `ingest_data`, `list_files`, `delete_file`, `read_chunk_neighbors`).
- На CLI `stderr`.

Уберите `BASE_DIR` (или удалите `BASE_DIRS`), чтобы скрыть предупреждение.

**Прunedение вложенных корней** — если один настроенный корень находится внутри другого после разрешения realpath, вложенный ребёнок отбрасывается для избежания дублирования результатов сканирования. Предупреждение о prune отображается тем же способом, что и предупреждение о приоритете. Сохранившийся родительский корень всё ещё определяет границу безопасности.

**Недействительный `BASE_DIRS`** — когда `BASE_DIRS` не является допустимым JSON-массивом непустых строк (неверный JSON, пустой массив, не-string элементы, ...), инструменты MCP, зависящие от корней, возвращают структурированную ошибку, а подкоманды CLI выходят с ненулевым кодом. Нет **молчаливого отката** к `BASE_DIR` или `cwd`. Инструмент MCP `status` остаётся вызываемым, чтобы вы могли диагностировать ошибку конфигурации через ваш MCP-клиент.

**Примеры MCP-клиента** — настройка нескольких корней:

Cursor (`~/.cursor/mcp.json`):
```json
{
  "mcpServers": {
    "local-rag": {
      "command": "npx",
      "args": ["-y", "mcp-local-rag"],
      "env": {
        "BASE_DIRS": "[\"/Users/me/Documents/work\",\"/Users/me/Projects/specs\"]"
      }
    }
  }
}
```

Codex (`~/.codex/config.toml`):
```toml

args = ["-y", "mcp-local-rag"]

[mcp_servers.local-rag.env]
BASE_DIRS = "[\"/Users/me/Documents/work\",\"/Users/me/Projects/specs\"]"
```

Claude Code:
```bash

  --env BASE_DIRS='["/Users/me/Documents/work","/Users/me/Projects/specs"]' \
  -- npx -y mcp-local-rag
```

**Примеры CLI** — вызовы с несколькими корнями:


### Первый запуск

Модель эмбеддингов (~90 МБ) загружается при первом использовании. Занимает 1-2 минуты, затем работает офлайн.

### Безопасность

- **Ограничение пути:** Только файлы в пределах настроенного корня (`BASE_DIR` или любой `BASE_DIRS` / `--base-dir`) доступны. Символические ссылки, разрешающиеся вне всех настроенных корней, и пути-предки siblings (например, `/foo/barista` для корня `/foo/bar`) отклоняются.
- **Только локально:** Никаких сетевых запросов после загрузки модели
- **Источники моделей** (все официальные репозитории HuggingFace):
  - Эмбеддер: [`Xenova/all-MiniLM-L6-v2`](https://huggingface.co/Xenova/all-MiniLM-L6-v2)
  - Визуальный профиль `fast`: [`HuggingFaceTB/SmolVLM-256M-Instruct`](https://huggingface.co/HuggingFaceTB/SmolVLM-256M-Instruct)
  - Визуальный профиль `quality`: [`onnx-community/Qwen2.5-VL-3B-Instruct-ONNX`](https://huggingface.co/onnx-community/Qwen2.5-VL-3B-Instruct-ONNX)
- **Точность визуальных подписей:** Профиль `quality` воспроизводит текст внутри изображения более точно, чем `fast`. Оба профиля выводят подписи, обернутые как `[Визуальный контент на странице N: …]`, но точное воспроизведение означает, что контролируемый злоумышленником текст внутри изображения — включая символы вроде `]`, которые визуально закрывают обёртку — может появляться верbatim в извлечённых чанках. Потребители LLM на downstream должны рассматривать извлечённые чанки как ненадёжные данные, а не как инструкции, независимо от формы обёртки.

<summary><strong>Устранение неполадок</strong></summary>

### "Результаты не найдены"

Документы должны быть загружены сначала. Выполните `"Перечислить все загруженные файлы"` для проверки.

### Загрузка модели не удалась

Проверьте подключение к интернету. Если за прокси, настройте параметры сети. Модель также можно [загрузить вручную](https://huggingface.co/Xenova/all-MiniLM-L6-v2).

Параметр по умолчанию — 100 МБ. Разделите большие файлы или увеличьте `MAX_FILE_SIZE`.

### Медленные запросы

Проверьте количество чанков с помощью `status`. Большие документы с множеством чанков могут замедлять запросы. Рассмотрите разделение очень больших файлов.

### "Путь вне BASE_DIR"

Убедитесь, что пути файлов находятся в одной из настроенных корневых директорий (`BASE_DIR`, любой `BASE_DIRS` или любой CLI `--base-dir`). Используйте абсолютные пути.

### "BASE_DIRS должен быть JSON-массивом..."

`BASE_DIRS` принимает только JSON-массив из одной или более непустых строк путей. Примеры:

- Действительно: `BASE_DIRS='["/Users/me/work","/Users/me/specs"]'`
- Недействительно: `BASE_DIRS=/a:/b` (синтаксис разделителя не поддерживается)
- Недействительно: `BASE_DIRS='[]'` (пустой массив)
- Недействительно: `BASE_DIRS='["",""]'` (элемент с пустой строкой)

При недействительном значении операции, зависящие от корней, завершаются с чёткой ошибкой вместо молчаливого отката. Инструмент MCP `status` остаётся вызываемым, чтобы вы моглиinspect диагностик.

### MCP-клиент не видит инструменты

1. Проверьте синтаксис файла конфигурации
2. Полностью перезапустите клиент (Cmd+Q на Mac для Cursor)
3. Протестируйте напрямую: `npx mcp-local-rag` должен работать без ошибок

<details>
<summary><strong>Часто задаваемые вопросы</strong></summary>

**Это действительно приватно?**
Да. После загрузки модели ничего не покидает ваш компьютер. Проверьте с помощью сетевого мониторинга.

**Могу ли я использовать это офлайн?**
Да, после того как необходимые модели закэшированы локально. Текстовая загрузка/поиск требует модель эмбеддингов. Визуальный режим PDF — опциональный и также требует модель VLM при первом использовании; загрузка составляет ~250 МБ для профиля `fast` по умолчанию (SmolVLM-256M) или ~2.9 ГБ для профиля `quality` (Qwen2.5-VL-3B), кэшируется в `CACHE_DIR` (по умолчанию: `./models/`).

**Как это сравнивается с облачным RAG?**
Облачные сервисы предлагают лучшую точность в масштабе, но требуют отправки данных внешне. Это жертвует некоторой точностью ради полной приватности и нулевой стоимости выполнения.

**Какие форматы файлов поддерживаются?**
PDF, DOCX, TXT, Markdown и HTML (через `ingest_data`). Пока нет: Excel, PowerPoint, изображения.

**Могу ли я изменить модель эмбеддингов?**
Да, но вы должны удалить вашу базу данных и перезарядить все документы. Разные модели производят несовместимые размерности векторов.

**Ускорение GPU?**
Включается опционально через `RAG_DEVICE`. Устройства передаются напрямую в ONNX Runtime. Поддержка GPU сильно зависит от вашей системы, версии Node.js и базового ONNX бэкенда. См. [исходный код устройств Transformers.js](https://github.com/huggingface/transformers.js/blob/main/packages/transformers/src/utils/devices.js) для живого списка поддерживаемых имён бэкендов. Если запрошенное устройство не может инициализироваться, сервер выбрасывает ошибку — установите `RAG_DEVICE=cpu` для отката.

**Могу ли я изменить точность эмбеддинга (dtype)?**
Включается опционально через `RAG_DTYPE` (по умолчанию `fp32`); принятые значения в таблице env-переменной выше. Распознаваемый dtype, которого модель не имеет, выдаёт ошибку и перечисляет доступные; нераспознаваемое значение (опечатка) молча откатывается к `fp32`. Изменение `RAG_DEVICE`/`RAG_DTYPE` меняет пространство эмбеддингов — удалите `DB_PATH` и перезаряжайте.

**Многосессионная поддержка?**
Нет. Предназначен для однорользовательского локального доступа. Многосессионность потребовала бы аутентификацию/контроль доступа.

**Как резервное копирование?**
Скопируйте директорию `DB_PATH` (по умолчанию: `./lancedb/`).
